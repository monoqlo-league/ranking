# MONOQLO PTランキング

ページ: https://monoqlo-league.github.io/ranking/

MONOQLO麻雀部 PTランキングのページ本体(`index.html`)と、集計元のデータ(月ごとの対局記録CSV・詳細成績・BANリストなど)を置くリポジトリ。
2026年11月に、データ用リポジトリ **monoqlo-data** をここへ集約した(monoqlo-data は廃止)。

## ページ

- ページのいちばん上に、チーム戦ランキング(event-ranking)への切り替えがある。チーム戦ランキング側にも、このページへの切り替えがある。
- **最初に読むもの**: このリポジトリの `index.json`(ファイル一覧。CSVを上げるたびに、このリポジトリの GitHub Actions が作り直す)。ここに載っている月と最終更新日時を使うので、GitHub の API(1時間60回までの制限)は使わない。`index.json` が読めないときだけ、以前と同じく API で探す。上げたばかりで一覧にまだ無い今月のCSVも、1回だけ確かめて拾う。
- **詳細成績の集計CSVは、成績のウィンドウを初めて開いたときに読む。** 月を切り替えただけでは読まない(最初の表示を軽くするため)。読み終わるまで、詳細成績の欄には「読み込み中…」と出る。
- 集計期間の下に **最終更新** の日時を出す。このリポジトリで、表示している月のCSVが最後に更新された日時(GitHubの記録。通算は、リポジトリ全体の最後の更新)。GitHubから取れないときは、代わりに「最終対局」として、データに入っている最後の対局の終了時刻を出す。
- 終わった月を表示しているときは、見出しに「完了」の印(`完了.png`)を重ねる。**翌月の1日を迎えたら、終わったと判断する。** 印は見出しの右端に重ね、下の行(集計期間・対局数・参加者)には重ねない。通算には印を付けない。入賞記録の「集計中」も、同じ判断にそろえている。
- 月のランキングでは、**前回チャンピオン**(データがある1つ前の月の1位)の名前の前後に 👑 を付ける。その人が今月まだ打っていなければ、表に出ないので 👑 も出ない。通算には付けない。
- プレイヤー名を押すと、成績・相性表が開く。中身は上から、入賞記録・詳細成績・戦績・相性表。
  - **詳細成績**: 牌譜から集計した成績(和了率・放銃率・副露率・立直率など)。項目・計算・見た目は、チーム戦ランキング(event-ranking)の詳細成績と同じ。項目を押すと、その項目の全員のランキングが下に出る(和了役一覧は、役ごとの和了回数)。ランキングの名前を押すと、その人の成績に切り替わる。
    - このリポジトリに、その月の集計CSV(`202509-summary.csv` のように、対局記録の名前に `-summary` を付けたもの)があるときだけ出る。無い月は、欄ごと出さない。
    - **通算には出さない**(全期間の集計CSVがそろうまで保留)。
    - 集計CSVは、1行が「1対局の1人」。対局記録とは「ゲームID=牌譜リンク」で結び付け、その対局の中の名前でプレイヤーを決める。対局記録にない対局の行は使わない。
    - 「最大スコア」だけは集計CSVではなく、対局記録の終了時点棒(「N位PT」の列)のいちばん大きい値。
    - BANの人は、項目のランキングでも順位を付けず、最後に並べる。
  - **戦績**: そのプレイヤーの対局を新しい順に並べた一覧。1局につき1行で、日付のあとに、1位から4位まで全員の名前・終了時の点棒・獲得PTを並べる。そのプレイヤーの欄には色を付ける。表示している月(または通算)の対局が対象。ほかの人の名前を押すと、その人の成績に切り替わる。
  - 終了時点棒は、対局記録CSVの「N位PT」の列の値。
  - **相性表**: 見出しの横の「?」を押すと、各列の意味・並び順・対象の範囲・読むときの注意が開く。もう一度押すと閉じる。表の見出しの「同卓数」「獲得PT」を押すと並べ替えられる(最初は獲得PTの大きい順。同じ見出しをもう一度押すと小さい順)。
- 集計元のデータ(月ごとの対局記録CSV・`ban.csv` など)は、このリポジトリの直下に置く。CSVの更新手順や集計のルールは、下の「データ」以降を参照。
- ページは開くたびに、このリポジトリのファイルを読み込んで集計する。
- データを置くリポジトリは `index.html` の `const DATA_REPO="ranking";` で決まる(このリポジトリの名前と同じにしておく)。

# データ

## ファイル名のルール

対局記録のCSVは **`data` フォルダの中** に、**1シーズン(1か月)につき1ファイル**、名前は **年4桁+月2桁.csv** にして置く(2026年11月に直下から `data` フォルダへ移した)。

| シーズン | ファイル名 |
|---|---|
| 2026年9月 | `202609.csv` |
| 2026年10月 | `202610.csv` |
| 2027年1月 | `202701.csv` |

- 「今月のランキング」には、いちばん新しい月のファイルが表示される。
- 「通算ランキング」は、すべての月のファイルを合計したもの。
- 名前がルールと違うファイルは読み込まれない。

## ランキングの更新手順(更新担当者向け)

1. 雀魂の大会管理画面から、そのシーズンの対局記録のCSVを書き出す。
2. ファイル名を、そのシーズンの **`年月.csv`**(例: `202610.csv`)に変える。
3. このリポジトリのファイル一覧で **`data` フォルダを開いてから**、ページ上部の **「Add file」→「Upload files」** を押す(フォルダを開かずに上げると直下に置かれ、ランキングに出ない。点検が Discord に知らせる)。
4. CSVを画面にドラッグ&ドロップする。同じ名前のファイルがあれば上書きされる。
5. 下の **「Commit changes」** を押す。
6. 1〜2分待ってから、ランキングのページを再読み込みする。

シーズン途中で何度更新してもよい。同じ月のファイルを、その時点までの全対局が入ったCSVで上書きする。

### 注意

- 前の月のファイルは消さない。消すと、過去のランキングと通算成績からその月が消える。
- 「非表示状態」が yes の対局は集計に含めない。
- 同じ対局(同じ牌譜)が2つの月のファイルに入っていても、通算では1回だけ数える。
- 間違ったファイルを上げてしまっても、そのファイルを開いて「History」から前の版に戻せる。困ったら管理者に連絡する。
- 数分たっても変わらないときは、ブラウザの再読み込み(スマホなら一度タブを閉じて開き直す)を試す。

## 詳細成績の集計CSV(summary フォルダ)

牌譜から集計した成績(和了率・放銃率・副露率・立直率など)を、プレイヤーの成績ウィンドウの「詳細成績」に出すためのCSV。牌譜の成績を書き出す拡張機能が出力したものを、そのまま置く。

- **`summary` フォルダの中**に置く。名前は、その月の対局記録の名前に **`-summary`** を付ける(`202509.csv` なら **`summary/202509-summary.csv`**)。
- 置いてある月だけ、詳細成績が出る。無い月は何も出ない(ランキングや相性表には影響しない)。
- 通算の詳細成績は、まだ出さない(全期間の集計CSVがそろうまで保留)。
- 中身は、1行が「1対局の1人」。対局記録とは「ゲームID=牌譜リンク」で結び付けるので、**同じ月の対局記録と組にして置く**。対局記録にない対局の行は使われない。
- 月の途中で対局が増えたら、対局記録と同じように、その時点までの全対局が入ったCSVで上書きする。集計CSVの対局が対局記録より少ないときは、詳細成績に「対局記録は○対局」と出る。
- アップロードは、リポジトリのファイル一覧で **`summary` フォルダを開いてから**「Add file」→「Upload files」を押す(フォルダを開かずに上げると直下に置かれる。その場合もページには出る)。

## プレイヤーの集計方法

- CSVのプレイヤー名は `[JP][141442184]パラセクト。` の形で記録されている。集計は表示名ではなく、名前の前の **プレイヤーID(数字)** で行う。
- IDは雀魂のアカウントごとに決まっていて、名前を変えても変わらない。そのため、途中で名前を変えた人(例:「パラセクト、」→「パラセクト。」)も同じ人として合算される。
- 逆に、別人がたまたま同じ名前でも、IDが違えば別々に集計される。
- 画面に出す名前は、各月のランキングではその月の最新の対局での名前、通算ランキングでは全期間で最新の対局での名前。
- IDの桁数は人によって違う(8桁・9桁など)。桁数は関係なく、番号が同じなら同じ人として扱う。

## BANリスト(ban.csv)

不正によりBANしたプレイヤーは `ban.csv` に書く。

BANの対象は、**麻雀のゲーム性を損なう不正**(チーミングやゴースティングなど)に限る。マナーや言動の問題など、対局の公正さに関わらない理由ではBANリストに載せない。

```
プレイヤー,BAN月,備考
[JP][130865092]ゆあんぴょん,202609,
```

- 1列目はCSVの表記そのまま(`[JP][ID]名前`)。判定に使うのは **ID(数字)だけ** で、名前はメモ。数字だけ書いてもよい。
- 2列目はBANした月(年4桁+月2桁)。3列目の備考は自由(空欄可)。
- **BAN月以降の月**と**通算**では、成績(PT・対局数など)はそのまま表示し、順位の対象外として最下位に「BAN」と表示する。並べ替えても最下位のまま。
- **BAN月より前の月**は、順位・入賞記録ともそのまま。
- BAN月以降は入賞の対象外になり、ほかのプレイヤーの順位が繰り上がる。
- 追加するときは1行足して上書きアップロードする。ファイルが無ければBANなしとして扱う。

## BAN・アカウント変更の登録ページ(list-edit.html)

https://monoqlo-league.github.io/ranking/list-edit.html (管理者用。ランキングからはリンクしない)

- 「GitHubでログイン」(アップロードページと同じ仕組み。アップロードページでログイン済みなら、そのまま使える)→ タブで「BAN」か「アカウント変更」を選ぶ → 参加者から対象者を選ぶ → 月(対局記録のある月と、その翌月から選ぶ)→「登録する」。
- 登録すると `ban.csv` か `account-change.csv` に1行足して、このリポジトリに直接保存する。すでに載っている人は選べない。
- 消す・直すときは、これまでどおりCSVを直接書き換える。
- このページで「GitHubでログイン」を押して使うには、GitHub App の Callback URL に `https://monoqlo-league.github.io/ranking/list-edit.html` を足しておく(足していなければ、アップロードページでログインしてから開く)。

## アカウント変更者リスト(account-change.csv)

アカウントを変えたプレイヤーの、**元のアカウント**を `account-change.csv` に書く。

```
プレイヤー,変更月,備考
[JP][122060292]しとらす@神速,,
```

- 1列目はCSVの表記そのまま(`[JP][ID]名前`)。判定に使うのは **ID(数字)だけ**。数字だけ書いてもよい。
- 2列目の変更月(年4桁+月2桁)は記録用で、空欄でよい。3列目の備考は自由(空欄可)。
- 載せたアカウントは **通算ランキングだけ** 順位の対象外になる(成績はそのまま)。順位の欄は「アカ変」と出て、順位のある人の下・BANの上に並ぶ。各月のランキングはこれまでどおり。

## ファイル一覧(index.json)とCSVの点検

CSVをアップロードすると、GitHub Actions が自動で次の2つを行う(数十秒〜1分ほど)。仕組みは `.github/workflows/build-index.yml` と `.github/build-index.py`。

1. **`index.json` を作り直す。** ファイルの一覧と、ファイルごとの最終更新日時・対局数が入る。ランキングページはこれを最初に1回だけ読むので、GitHub の API(1時間60回までの制限)を使わずに済み、表示が速く安定する。**手で書き換えたり消したりしない。**
2. **CSVを点検する。** 今回上げたCSV(と、同じ大会・同じ月の関係するCSV)に気になる点があれば、Discord に知らせる。点検する内容:
  - ファイル名がルールと違う(ランキングで読み込まれない)
  - 必要な列が足りない、プレイヤー名や点数が読めない行がある
  - 4人の点数の合計が合わない、同じ対局が2回入っている
  - 開始時間がファイルの月と違う対局がある、別の月のファイルにも同じ対局がある
  - 詳細成績のもと(summary)のゲームIDが対局記録にない、名前で結び付かない、summary フォルダの外に置いてある
  - ban.csv に読めない行がある
  - **チーム戦の対局記録を誤って上げていないか**: event-data の対局記録(`-gamesN.csv`)にある対局が入っている
  - **前の版にあった対局がなくなっていないか**: 月のCSVは毎回その月の全対局を入れて上書きするので、ふつうは減らない。減っていたら、別の月やチーム戦のCSVを上げた可能性がある(チーム戦の対局が減った分は数えない)

- 問題のある対局には、**分割CSV(splitdata-download の `YYYYMM-連番.csv`)の何番にあたるか** を添える(例: `〔分割CSV: 202608-03〕`)。番号は、月のCSVを開始時間の古い順に並べて10対局ずつに分けたときの番号で、分割したときと同じ決め方。分割したあとで月のCSVを書き換えた場合は、番号がずれることがある。
- 詳細成績の集計CSVで、まだ集計されていない対局があるときは、その分割CSVの番号を「(情報)」として添える。これだけのときは送らない(手動実行のときは、結果と一緒に送る)。
- 点検の結果は、問題があるときだけ送る。「Actions」タブ →「データの一覧と点検」→「Run workflow」で手動実行すると、全部のCSVを点検して、問題がなくても結果を送る。
- 送り先は、Secret の `DISCORD_ADMIN_WEBHOOK_URL`(管理者だけのチャンネル用。任意)。無ければ、更新通知と同じ `DISCORD_WEBHOOK_URL` に送る。登録のしかたは「Discordへの更新通知」と同じ。
- 点検は知らせるだけで、CSVを書き換えたり、アップロードを止めたりはしない。誤ったCSVを上げたときは、正しいCSVで上書きするか、ファイルの「History」から前の版に戻す。
- 分割CSV(splitdata-download)の側でも、チーム戦の対局は分割に入れない。前の版から10対局以上なくなった月は、正しいCSVに戻るまで分割しない。
- アップロード直後の1分ほどは、`index.json` がまだ古いことがある。そのあいだに新しく足したファイルは、ランキングに出るのが少し遅れることがある。
- Actions の画面に「index.json を更新(自動)」という更新が並ぶが、正常な動き。

## Discordへの更新通知

対局記録(`data/YYYYMM.csv`)をアップロードすると、Discordのチャンネルに自動で通知が届く。増えた対局数とランキングのURLが載る。詳細成績(`summary` フォルダ)・`ban.csv`・README の変更では通知しない。

通知先の設定(管理者が最初に1回だけ行う):

1. Discordで、通知したいチャンネルの「チャンネルの編集」→「連携サービス」→「ウェブフック」→「新しいウェブフック」を押す。名前とアイコンは自由。
2. 「ウェブフックURLをコピー」を押す。
3. このリポジトリの「Settings」→「Secrets and variables」→「Actions」→「New repository secret」を押す。
4. Name に **`DISCORD_WEBHOOK_URL`**、Secret にコピーしたURLを貼り付けて「Add secret」を押す。

- ウェブフックURLを知っている人は誰でもそのチャンネルに投稿できる。URLは Secret にだけ置き、ファイルや会話には書かない。漏れたら Discord でウェブフックを削除して作り直し、Secret を更新する。
- Secret が未設定のあいだは、通知を送らずに終わる(エラーにはならない)。
- 中身が前と同じCSVを上げ直した場合は、変更なしとして扱われ通知しない。
- 設定の確認は「Actions」タブ →「Discordへ更新を通知」→「Run workflow」で、テストの通知を送れる。
- 通知の動作は「Actions」タブで確認できる。仕組みは `.github/workflows/discord-notify.yml` と `.github/notify-discord.py`。

## 分割CSVの自動作成

対局記録(`data/YYYYMM.csv`)をアップロードすると、[splitdata-download](https://github.com/monoqlo-league/splitdata-download) に、まだ分割していない対局を10対局ずつのCSVにして足すよう知らせる。分割のきまりは splitdata-download の README を参照。

知らせるためのトークンの設定(管理者が最初に1回だけ行う):

1. GitHub の右上のアイコン →「Settings」→「Developer settings」→「Personal access tokens」→「Fine-grained tokens」→「Generate new token」を押す。
2. 次のように入れて「Generate token」を押す。
   - Token name: 何でもよい(例:`split-dispatch`)
   - Expiration: 期限。切れたら作り直して Secret を入れ替える
   - Resource owner: **`monoqlo-league`**
   - Repository access: **Only select repositories** → **`splitdata-download`** だけ
   - Permissions → Repository permissions → **Contents** を **Read and write**(ほかは触らない)
3. 表示されたトークンをコピーする(この画面を閉じると二度と見られない)。
4. このリポジトリの「Settings」→「Secrets and variables」→「Actions」→「New repository secret」で、Name に **`SPLIT_DISPATCH_TOKEN`**、Secret にトークンを貼って「Add secret」を押す。

- Resource owner に `monoqlo-league` が出ない、または承認待ちになるときは、組織の「Settings」→「Personal access tokens」で fine-grained トークンを許可する(組織のオーナーが行う)。
- Secret が未設定・期限切れのあいだは、すぐには分割されない。splitdata-download が1日1回(朝4時ごろ)自分で確かめて分割する。
- 動作は「Actions」タブ →「分割CSVの作成を頼む」で確認できる。仕組みは `.github/workflows/split-dispatch.yml`。

## ファイル

- `index.html` … ランキングのページ本体
- `完了.png` … 終わった月の見出しに重ねる印。差し替えるときは、同じ名前で上書きする。背景が透明なPNGにする
- `data/YYYYMM.csv` … 各シーズンの対局記録
- `summary/YYYYMM-summary.csv` … 各シーズンの詳細成績の集計(牌譜から書き出したもの。ある月だけ)
- `ban.csv` … BANリスト
- `account-change.csv` … アカウント変更者リスト
- `index.json` … ファイル一覧(自動で作られる。手で変更しない)
- `.github/` … Discordへの更新通知、ファイル一覧・点検、分割CSVの作成依頼の仕組み(変更しない)
